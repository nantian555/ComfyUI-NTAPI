# 视频兼容模式

新增三个节点：`NTAPI-视频生成（兼容模式）`、`NTAPI-视频编辑（兼容模式）`、`NTAPI-视频任务获取`。

**这些节点已做本地模拟验证，但 NTAPI 生产兼容性未验证。** 模型广场列出了 omni-flash 系列，公开详情仍提供通用聊天示例，未确认其视频协议。不能据此宣称这五种功能已在 NTAPI 服务端可用。

## 使用

1. 生成或编辑节点填写密钥（也支持 `NTAPI_API_KEY`）、模型、接口地址和输入。
2. 输出 `任务ID` 接到任务获取节点，并使用相同服务地址和密钥。
3. 任务获取输出 `视频` 接 ComfyUI 的 `Save Video`。
4. 超时后将原任务 ID 填入获取节点继续查询，勿重复运行提交节点。可以从控制台取回任务 ID；不会把任务保存在全局后台队列。

| 用法 | 输入与模型选择 |
| --- | --- |
| 文生视频 | 选择文生视频模式，填写提示词 |
| 图生视频 | 选择图生视频模式，连接首帧 |
| 首尾帧 | 选择首尾帧模式，分别连接首帧和尾帧 |
| 多参考图 | 图片先组成 IMAGE 批次，再连接参考图批次；可选择 components 模型 |
| 视频编辑 | 连接原生 VIDEO 或填写视频 URL，同时提供时 URL 优先；可选择 edit 模型 |

不截断参考图批次。首尾帧通常应各接一张图片；若输入批次，将依首帧批次、尾帧批次的顺序全部发送。没有采用质量导向的数量限制；输入是否被服务接受由服务决定。

尺寸是可填写的 `宽x高` 字符串；模型预设不自动改写尺寸和时长。选择 1080p/4k 模型时，需按供应商要求填写匹配参数。生成模式只读取当前模式对应的图像输入。

## 使用的协议

- 生成：`POST {接口地址}/videos`，JSON 字段 `model`、`prompt`、`seconds`（字符串）、`size`。
- 图生/首尾帧：有序的 `images` Data URL 列表，`generation_type: frame`。
- 多参考图：`images` Data URL 列表，`generation_type: reference`。
- URL 编辑：同一 POST 路径，JSON `images: [视频URL]`。
- 本地视频编辑：同一路径，multipart `input_reference` 为 MP4 文件，不依赖其他图床或上传服务。
- 创建响应：顶层 `id` 或 `task_id`；提交后立即输出 ID。
- 查询：`GET {接口地址}/videos/{任务ID}`，等待 queued/pending/processing/running/in_progress/submitted，直到完成或失败。
- 完成：读取顶层、`result` 或 `data` 对象中的 `video_url`/`url`；没有 URL 则下载 `/videos/{任务ID}/content`。

这套适配依据本地节点的请求字段和公开视频任务约定编写，不导入其他插件，也不会转发到其他中转站。首尾帧、多参考图和编辑的 NTAPI 字段映射仍是待实测假设。如果服务使用不同协议，需要修改对应适配；仅更改模型名不能保证兼容。

## 错误、安全与存储

- 提交只请求一次，无自动重试；超时不能判断服务端是否已受理。
- 查询失败和超时保留任务 ID；获取节点重新执行会再次查询，不提交生成。
- 等待期间支持 ComfyUI 中止，单次网络请求受超时限制；最大等待秒数针对轮询，下载另有连接/读取超时。
- API 密钥只发送给配置的服务，同源结果下载可携带密钥；外部结果地址不携带密钥。不跟随重定向。
- 视频下载到 ComfyUI 临时目录并验证可读取的视频流；失败/中止删除不完整文件，成功文件保留供下游节点读取。需要永久保存请连接 Save Video。
- 本地视频输入通过原生 VIDEO `save_to` 导出 MP4，因此保留其剪辑窗口/裁剪语义；必要时由 ComfyUI 编码。不会自动将文件上传到另一个图床。

## 示例

`examples/video-generate.workflow.json` 提供四种生成模式的基础连接；按模式连接首帧、尾帧或参考图批次。
`examples/video-edit.workflow.json` 提供视频 URL 编辑示例；也可接入原生 Load Video。
两个示例密钥留空，任务获取输出连接 Save Video。
